# 🐿️ NutOS Name & Identity
*Rodent, Inc. | SquirrelLabs Technologies*

---

## Brand Mission

NutOS branding should communicate three things immediately:

1. **User ownership** — the OS belongs to the user, not a vendor.
2. **Trust** — privacy and security are defaults, not upsells.
3. **Capability** — modern UX and broad software compatibility.

---

## Naming System

| Name | Scope | Meaning |
|---|---|---|
| **NutOS** | Operating system | Core platform identity |
| **NutKernel** | Kernel distribution | Hardened Linux base with NutOS modifications |
| **NutShell** | Compatibility layer | Unified runtime for Linux/Windows/Android/Web apps |
| **Acorn** | Desktop environment | Native UI shell and design language |
| **NutCage** | Sandboxing | Per-app isolation and permission enforcement |
| **Harvest** | Update manager | Signed updates + rollback workflow |
| **The Cache** | App store | Unified software discovery and install surface |

---

## Name Rationale

### Why “NutOS”

- **Memorable:** short, distinct, easy to pronounce globally.
- **Symbolic:** "nut" implies preparedness, storage, and efficiency.
- **Extensible:** supports a coherent ecosystem naming pattern.

### Why “Acorn”, “NutShell”, “Harvest”

The sub-brand system uses natural metaphors that map to product behavior:

- **Acorn** = the visible seed of user interaction (desktop shell).
- **NutShell** = protective and unifying compatibility abstraction.
- **Harvest** = reliable collection and delivery of updates.

## Logo & Visual Direction

### Core Symbol

- Primary symbol: simplified squirrel-tail spiral or acorn silhouette.
- Must remain recognizable at 16px and at large-format scale.

### Color System (Initial)

- **Nut Brown:** trust, warmth, stability
- **Forest Green:** openness, sustainability, security
- **Slate Gray:** technical precision
- **Accent Gold:** premium polish and focus states

> Final hex values and accessibility tokens are maintained in the Acorn design system package.

### Typography

- UI/System font: modern sans-serif optimized for readability.
- Technical docs: monospaced fallback only for code snippets.
- Headings should prioritize clarity over stylistic flair.

---

## Voice & Tone Guidelines

### Voice Attributes

- **Clear** (avoid vague claims)
- **Respectful** (user-first language)
- **Confident** (no hype-heavy exaggeration)
- **Practical** (show outcomes and tradeoffs)

### Preferred Language Patterns

- Say **“user controls”** rather than **“we allow users”**.
- Say **“opt-in”** rather than **“optional telemetry”** when applicable.
- Use plain verbs: *install, protect, verify, rollback, customize*.

### Avoid

- Fear-based marketing language.
- Hostile comparisons to users of other platforms.
- Ambiguous security claims without implementation context.

---

## Brand Consistency Rules

1. Always write **NutOS** (capital N, O, S).
2. Use official component names exactly as defined in this document.
3. Avoid creating unofficial sub-brands in external materials.
4. Product screenshots and demos must reflect current Acorn UI conventions.
